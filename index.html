01 / BEFORE YOU BEGIN

Understand the setup

Super Agent is a research prototype that runs as a DeepSeek Harness bundle, not a standalone model. Its worker presets have broad OS access; don't point them at your personal files.

01

Dedicated external SSD

Place Ubuntu's virtual disk and the Linux-side tools, Harness state and workspaces on the SSD. Some WSL host components remain on Windows.

02

Separate GitHub identity

Use a disposable repository and a dedicated bot user. Do not give the worker your primary GitHub credentials.

03

Human approval

Leave auto-merge disabled and proactive acceptance in observe mode. Review changes and logs yourself.

Security: DeepSeek documents the Router/Worker presets as danger-full-access. WSL alone is not a security boundary. For strong isolation, use a separate OS user/VM with only test credentials. The guide does not silently grant privileged access.
02 / INSTALLATION

Pick your installation path

Both paths end in the same Harness + Super Agent installation. Commands are provided for a Windows 11 host and an Ubuntu WSL2 environment on an external SSD.

Step zero — identify the external SSD

Open My Computer → right-click the SSD → Properties. Confirm its drive letter, free space, and filesystem. Never format the drive. The examples use E: only as a placeholder.

Choose a folder name or a relative subfolder path. The install commands and Codex prompt update automatically.

Use an NTFS-formatted SSD with at least 20–30 GB free. If your disk is exFAT or FAT32, do not run the WSL location command before choosing a compatible destination.

01

Enable WSL without a default distribution

PowerShell · Administrator
wsl --install --no-distribution
wsl --update
wsl --list --online

Restart Windows if prompted. Confirm that Ubuntu-24.04 appears in the online list before using that distribution name.

02

Install Ubuntu onto the SSD

PowerShell · SSD location
wsl --install -d Ubuntu-24.04 --location "E:\TunnelLab-AI\Ubuntu" --no-launch
wsl --list --verbose

On WSL builds that do not recognize --location, stop and update WSL; don't fall back to a default C: installation. For a dedicated restricted Linux user, follow the installer script or the security notes below before starting any agents.

03

Install basic Linux tools

Ubuntu · bash
sudo apt update
sudo apt install -y git python3 python3-venv tmux curl ca-certificates build-essential gh
# Install Node.js 24 using the maintained NVM project first:
# https://github.com/nvm-sh/nvm#installing-and-updating
# In a new Ubuntu shell, after NVM is installed:
nvm install 24
nvm use 24
npm install -g pnpm@11.7.0
node -v
pnpm -v
git --version
tmux -V
python3 --version
gh --version

The final commands check versions. Install Node.js 22.19+ (or 24+) and pnpm using their official Linux instructions, not an outdated Ubuntu package. Git must be 2.32+ and gh 2.48+.

04

Install the pinned Harness version

Ubuntu · bash
npm install -g @deepseek-ai/dsh@0.2.1-rc.3
dsh --version

The version is pinned by the upstream Super Agent deployment guide. Confirm compatibility before upgrading.

05

Prepare the project and dedicated profile

Ubuntu · bash
mkdir -p ~/src
cd ~/src
git clone https://github.com/deepseek-ai/dsh-superagent-prototype.git dsh-superagent
cd dsh-superagent
pnpm install
pnpm build
dsh superagent --from-default-profile web --dump-config > /dev/null
dsh plugin --profile superagent add "link:$PWD"

Run profile creation ONLY once on a new installation. On an existing profile, the creation command can overwrite settings; use the official Upgrade guide instead.

06

Configure the machine profile

Copy examples/profile.cordis.patch.yml to the dedicated Harness profile's cordis.patch.yml. Replace every placeholder, set a unique absolute stateDir, enable the webserver port 3082, and supply the dedicated GitHub CLI wrapper. See upstream Deployment for the exact schema.

07

Configure a separate GitHub bot identity

Ubuntu · bash
mkdir -p ~/.local/bin
cat > ~/.local/bin/gh-agent <<'EOF'
#!/bin/sh
GH_CONFIG_DIR="$HOME/.config/gh-agent" exec gh "$@"
EOF
chmod +x ~/.local/bin/gh-agent
gh-agent auth login
gh-agent api user --jq .login

Create the dedicated GitHub user and accept the test repository invitation manually. Only sign in as the bot for gh-agent. Don't reuse your main GitHub CLI credentials.

08

Start and configure Super Agent

Ubuntu · inside ~/src/dsh-superagent
scripts/dsh-superagent start
scripts/dsh-superagent status

Open the panel URL shown in the start output; select Superagent in the sidebar. Set Sources, Policy, Execution and Prompts in that order. If status reports setup pending, finish the missing settings rather than restarting repeatedly.

09

Prepare a separate test checkout and a safe first test

Initialize a disposable GitHub repository with README, invite a dedicated GitHub bot, clone with that bot's isolated gh-agent identity, and configure Settings → Execution → Prepare command from upstream Deployment. Set Eval and Execution to the working model (for example openrouter/free), select the same model in Open main Session, pause Executor and leave auto-merge off. Receive-mode Observe does not prevent explicitly addressed requests from becoming tickets; confirm safeguards before retrying.

Node 24.22.2 may report its process name as MainThread. If upstream start times out despite an active 3082 listener, check the script's node/dsh process-name detection. Review a minimal local compatibility patch rather than starting a duplicate or replacing dependencies. A startup-generated token URL must be opened privately with cookies retained.
03 / MODEL PROVIDER

Connect OpenRouter

Harness supports a custom OpenAI Chat Completions-compatible provider. Free OpenRouter models may work, but tool use, context limits and reliability vary; compatibility must be tested rather than assumed.

Settings → Models → Custom model API

Provider configuration
Provider ID: openrouter
Base URL: https://openrouter.ai/api/v1
API protocol: openai-completions
API Key: enter privately in Harness
Model ID: openrouter/free (automatic free-model routing; verify tool calling)

Select Fetch available models, check tool-calling support and test a small task. A free API tier does not guarantee unlimited requests or uninterrupted operation.

Costs and limits

The prototype's source code is MIT-licensed. Using a free model may cost $0 in model tokens within the provider's applicable limits. Storage, networking, paid models, retries and hosted compute can still cost money.

Do not rotate multiple accounts to evade free-tier limits. Use one account or independent providers under their terms.
